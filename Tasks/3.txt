#value — приватное поле. Доступ к нему возможен только внутри класса.

Стрелочная функция — это сокращённая запись анонимной функции:
// Обычная функция
	function (item) { return item.getLength() === length; }

// Стрелочная функция
	item => item.getLength() === length;

	параметр / (параметры) => тело_функции 

Правила сокращения:
	Если параметр один — скобки вокруг него можно опустить: item => ...
	Если тело — одно выражение, {} и return можно опустить (неявный возврат): item => item.getLength() === length
	Если параметров несколько или нет — нужны скобки: () => ..., (a, b) => ...
	Если тело — блок с несколькими строками — нужны {} и явный return.


н-р:
	arr.filter(item => item.getLength() === length)
		1. filter перебирает массив arr.
		2. Для каждого элемента item вызывает стрелочную функцию.
		3. Функция возвращает true/false (предикат).
		4. filter оставляет только те элементы, для которых вернулось true.

	this не используется — стрелочные функции не имеют своего this, они берут его из окружающего контекста. 
	Внутри filter/forEach это как раз удобно: не нужно беспокоиться о привязке this.

	Работает так же, но более громоздко. Главное отличие — this: в стрелочной функции this берётся из окружающего контекста 
	(здесь он вообще не нужен), в обычной function — свой собственный.


	\\b — граница слова (начало или конец слова). В шаблонной строке нужно писать \\b, чтобы в саму регулярку попал \b

Символ # перед именем делает поле приватным: снаружи объекта к нему нельзя обратиться напрямую (director.#name вызовет ошибку). Это часть инкапсуляции.

Конструктор — метод, который вызывается при создании объекта через new Director(...). Принимает два аргумента и сохраняет их в приватные поля. this здесь — ссылка на создаваемый объект.

//-----------------------------------------------------------------------------
Геттеры — специальные методы, которые позволяют читать приватные поля снаружи как обычные свойства:
	director.name            // работает (вызывается get name())
	director.#name           // ошибка (поле приватное)

Геттер не требует вызова со скобками: пишется director.name, а не director.name().

//-----------------------------------------------------------------------------
	class News extends TvProgram {
    	#anchor; // Ведущий

	extends TvProgram — наследование. News получает все поля и методы TvProgram и добавляет своё поле #anchor (ведущий).
	

//-----------------------------------------------------------------------------
	constructor(title, duration, anchor) {
	        super(title, duration);
	        this.#anchor = anchor;
	    }

	super(title, duration) — вызов конструктора родителя TvProgram. Без него JS выдаст ошибку: наследник обязан сначала инициализировать родителя.


//-----------------------------------------------------------------------------
	class Movie extends TvProgram {
	    #director; // Объект класса Director
	    #genre;

	Movie наследуется от TvProgram и содержит объект другого класса Director — это и есть композиция.

	Наследуется от Movie. Конструктор вызывает super(title, duration, director, genre) — то есть конструктор Movie, который уже сам вызовет конструктор TvProgram.
		Цепочка: FeatureFilm → Movie → TvProgram.

	Класс — это «чертёж», шаблон, описывающий, какие поля и методы будут у объекта.
	Объект — конкретный экземпляр класса, созданный через new.

//-----------------------------------------------------------------------------
	Инкапсуляция — принцип ООП: скрывать внутреннее устройство объекта, предоставляя только нужный интерфейс.

//-----------------------------------------------------------------------------
	Наследование (extends) — механизм, при котором один класс (наследник) получает все свойства и методы другого (родителя) и может их дополнять или переопределять.

	TvProgram

//-----------------------------------------------------------------------------
	Ключевое слово super используется в наследниках для обращения к родителю:

		1. В конструкторе — вызов конструктора родителя:
			constructor(title, duration, anchor) {
			    super(title, duration);     // вызывает TvProgram.constructor
			    this.#anchor = anchor;
			}

			Правило: super(...) должен идти до первого обращения к this. Иначе JS выдаст ошибку.

		2. В методах — вызов родительской версии метода:
			showInfo() {
			    return `${super.showInfo()} | Ведущий: ${this.#anchor}`;
			}

			super.showInfo() вызывает версию из TvProgram, а затем мы дополняем её.

//-----------------------------------------------------------------------------
	this — ссылка на текущий объект, у которого вызван метод.
		class Director {
		    constructor(name) {
		        this.name = name;    // this = создаваемый объект
		    }
		    getDetails() {
		        return this.name;    // this = объект, у которого вызван getDetails
		    }
		}

	this определяется в момент вызова:
		const d = new Director("Нолан");
		d.getDetails();   // this === d

	Если метод вызывается через super, то this внутри родительского метода всё равно указывает на наследника. 
	Поэтому в TvProgram.showInfo() this.type вернёт значение из News, а не "Программа". Это основа полиморфизма.

//-----------------------------------------------------------------------------
	Композиция — способ связи классов, при котором один объект содержит другой как поле.

		class Movie {
		    #director;                     // ← поле-объект Director
		    constructor(title, duration, director, genre) {
		        this.#director = director; // сохраняем объект внутри
		    }
		}

		const nolan = new Director("Кристофер Нолан", 25);
		const movie = new FeatureFilm("Одиссея", 172, nolan, "Фантастика", 250000000);

		Movie содержит Director. Без режиссёра фильм не имеет смысла. Это классический пример «has-a» («фильм имеет режиссёра»).

		Почему Director — композиция, а не наследование?
		Потому что FeatureFilm — это не разновидность Director. Фильм имеет режиссёра, но не является режиссёром. Если бы мы сделали class FeatureFilm extends Director, это была бы логическая ошибка.

		Преимущества композиции:
		1. Гибкость: можно заменить режиссёра, не меняя класс фильма.
		2. Переиспользование: Director можно использовать и в фильме, и в сериале, и в мультфильме.
		3. Слабая связанность: Movie знает только то, что у Director есть метод getDetails(). Внутренности режиссёра его не интересуют.

//-----------------------------------------------------------------------------
	instanceof - Оператор проверяет, является ли объект экземпляром класса (или его наследника):

		directorNolan instanceof Director   // true
		directorNolan instanceof Movie      // false
		new FeatureFilm(...) instanceof Movie  // true (FeatureFilm наследуется от Movie)

Code convention
	Соглашения о коде — не правила языка, а договорённости сообщества.

	Ключевые для JS:

	Что						Стиль				Пример
	Классы					PascalCase			TvProgram, FeatureFilm
	Методы/переменные		camelCase			showInfo, directorNolan
	Приватные поля			#camelCase			#title
	Константы				UPPER_SNAKE_CASE	MAX_DURATION
	Отступ					2 или 4 пробела		везде одинаково
	;						ставить				const x = 5;

оберём воедино:

	1. Иерархия — цепочка TvProgram → Movie → FeatureFilm. Каждый уровень добавляет свою специфику. Общие поля и методы — в родителе, частные — в наследниках.

	2. Композиция — Movie содержит Director. Это позволяет переиспользовать класс Director и не смешивать понятия «фильм» и «режиссёр».

	3. Инкапсуляция — все поля приватные (#title, #director). Доступ — через геттеры. Это защищает данные.

	4. Полиморфизм — единый вызов program.showInfo() даёт разный результат для News, FeatureFilm, Cartoon. Работает благодаря переопределению методов и this/super.

	5. super — вызывает родительский конструктор и родительские методы, чтобы не дублировать логику.

	6. this — всегда указывает на текущий объект. Именно поэтому this.type в родительском showInfo() возвращает значение из наследника.

	7. DRY — общий код в одном месте (getCommonInfo, showInfo, getDetails).

	8. Code convention — единообразное оформление делает код читаемым для любого разработчика.
